## Scenario

You maintain a small Node.js calculation library. A reporter says that doubling `2` returns `3` rather than `4`. They attach a `.proofissue` artifact containing a failing reproduction and the relevant implementation file.

The reporter expects:

- command: `node test/reproduction.mjs`
- exit code: `1`
- stderr contains: `Expected 4 from calculate(2)`
- network: disabled
- timeout: 60 seconds

## Task 1 — Review the Proposed File Roles

The recorder preview shows:

```text
Files that may be replaced when checking current code
  test/reproduction.mjs

Files kept exactly as recorded
  src/calculate.mjs
```

Questions:

1. Is either file in the wrong group?
2. What do you expect each group to do during fix verification?
3. What words would make the distinction clearer?

Do not explain the intended model until the participant answers.

## Task 2 — Decide Whether to Replay

Mock inspection summary:

```text
ProofIssue artifact version 1

Runtime
  Node.js 24 in an approved digest-pinned Linux image

Command
  node test/reproduction.mjs

Recorded files
  reproduction: test/reproduction.mjs
  subject:      src/calculate.mjs

Expected failure
  exit code: 1
  stderr contains: Expected 4 from calculate(2)

Limits
  network: disabled
  timeout: 60 seconds
  memory: 512 MiB
  CPUs: 1
  processes: 64

Redaction
  enabled; no findings

No command was executed during inspection.
```

Questions:

1. Is this enough information to decide whether you would replay the artifact?
2. What is missing?
3. Which information feels unnecessary?
4. What would make you refuse replay?

## Task 3 — Interpret Snapshot Replay

Mock result:

```text
Result: reproduced

Matched evidence
  exit code was 1
  stderr contained: Expected 4 from calculate(2)

Execution controls
  approved image digest used
  network disabled
  resource limits applied
  temporary workspace removed
```

Questions:

1. What does this result prove?
2. What does it not prove?
3. What would you do next as the maintainer?

## Task 4 — Choose a Fix-Verification Mode

You change `src/calculate.mjs` so the calculation is correct. You want to keep the reporter's test unchanged while using your corrected implementation.

Questions:

1. Would you use snapshot replay or replay against the current checkout?
2. Which files should come from the artifact?
3. Which files should come from your checkout?

Mock result after declared-path substitution:

```text
Result: not_reproduced

Differences
  expected exit code 1; actual exit code 0
  expected stderr text was absent

Current-checkout scope
  substituted: src/calculate.mjs
  undeclared checkout files were not read
  this result covers only the listed substitution
```

Question: How would you describe this result in your own words?

## Task 5 — Test the Structural-Fix Limitation

Consider three alternative fixes:

1. `src/calculate.mjs` starts importing a newly added `src/double.mjs`.
2. `src/calculate.mjs` is deleted and replaced by `src/arithmetic.mjs`.
3. Only `src/calculate.mjs` changes internally.

Questions:

1. Which fixes can declared-path substitution represent?
2. What should ProofIssue do for the others?
3. Would this limitation still leave the feature useful?

## Demand Questions

Ask about evidence, not general interest:

1. Tell us about the last Node.js bug report that was difficult to reproduce.
2. Which part of this workflow would have reduced work, if any?
3. Would you ask that reporter to create this artifact? Why or why not?
4. How much reporter setup would be acceptable?
5. What would prevent your project from accepting an artifact like this?
6. Would you run it locally, in CI, in a disposable virtual machine, or nowhere?

## Facilitator Notes and Intended Model

- In Task 1, the groups are intentionally reversed. The test should remain the frozen reproduction; the implementation should be the replaceable subject.
- Snapshot replay proves that the declared artifact reproduced its configured evidence under the reported controls. It does not prove root cause or guarantee all future runs.
- Current-checkout replay should be chosen for the simple one-file correction.
- The new-file and rename/delete fixes are not representable by version 1 declared-path substitution. New undeclared files are invisible; missing declared paths fail preparation. A new artifact or future manifest-evolution feature is needed.
- The internal one-file edit is representable.

Record whether the participant reaches these conclusions without coaching, where they hesitate, and what language they naturally use. Do not count exposure to the answer key as a successful task.
